# Indexed feature extraction

`shiro-fextr` implements the original index-driven WAV conversion and extraction
workflow. `index::read` and `batch::extract_file` expose the same operations to
Rust callers. The default extractor is MFCC12 with delta and acceleration at
16 kHz. All original options are retained: index path, `-d` directory, `-e`
input extension, `-x` extractor, `-r` output rate, `-n` normalization and `-D`
dither. Additional options are `--seed`, `--legacy-resample`, `--lua` and
`--sptk-directory`.

The three bundled xxcc extractors run entirely in Rust. Select their original
names, with or without the `extractors/` prefix:

- `extractor-xxcc-mfcc12-da-16k`
- `extractor-xxcc-mfcc12-dae-16k`
- `extractor-xxcc-plpcc12-da-16k`

They use frame length 512, hop 80, order 12, and the original filterbank options.
Their feature rate remains 16 kHz even when `-r` specifies another audio rate,
as in the source scripts. They persist `.raw` and `.param` files. Default dither
starts a fresh original OS-specific sequence for every input file, matching
the original separate wav2raw processes.

The bundled `extractor-sptk-mfcc12-da-16k` workflow still uses external SPTK
programs. Rust connects `frame -l 512 -p 80` to `mfcc -l 512 -m 12 -s 16`,
then runs `delta -l 12 -d -0.5 0 0.5 -d 0.25 0 -0.5 0 0.25`. It retains
`.mfcc` as well as `.raw` and `.param`. Each child exit status is checked,
including the producer in the pipeline. A failed launch or consumer reaps
unfinished children. Programs are found on PATH or in `--sptk-directory`.
Use the original binary32 SPTK 3 series. SPTK 4 changed its ordinary stream
format to binary64 and is not interchangeable with this preset.

An existing custom `.lua` file takes precedence over a bundled preset name.
Other extractor paths also invoke external Lua. The script must return the
original callback accepting execution helper, stem, raw path and executable
prefix. Local Lua modules, paths containing spaces and Windows extended paths
are supported. The corrected global `try_execute` helper is also available.
Lua script output conventions remain under the callback's control.

## Intentional corrections

- Blank index rows are skipped rather than silently ending processing. CRLF
  rows lose both newline characters. Literal spaces within phoneme fields
  still preserve empty tokens, as in the original index parser.
- Malformed index rows report their physical line number. The complete index
  is parsed before any batch output is created.
- `-r 0` correctly retains the source rate. The Lua tool compared a string
  option to numeric zero and could accidentally request invalid resampling.
- A compound input extension still produces the stem's `.raw` file, which
  the extractor consumes. The original combination could disagree about
  the intermediate basename.
- Input/output aliases are rejected before writing. Silent normalization and
  corrected resampling follow `audio-compatibility.md`; legacy boundary
  behavior remains explicitly selectable.
- Failed SPTK producers and failed Lua shell commands now return failure.
  Numeric nonzero Lua 5.1 shell statuses are not mistaken for success.
- Local Lua module loading uses literal filenames rather than path templates.
  Windows extended paths can contain `?`, which Lua templates would replace.

## Evidence and reproduction

Upstream SHIRO is pinned to `203ef7b71bf382c8b5ce3f86b8116f63265e2711`.
The three `c-fextr-*.bin` fixtures were generated by its unchanged
`shiro-fextr.lua`, bundled extractor scripts, original C wav2raw and original
xxcc pipeline with ciglet `895ba9b1c0eabee83d3544208bbc82420efa3206`.
The input is `c-audio-input.wav`, copied to `sample.wav` beside an index row
`sample,aa bb`. Invoke Lua with the index, `-d` input directory and `-x` the
absolute bundled extractor path without `.lua`; copy `sample.param`.
The C builds use `FP_TYPE=float`, `-O2`, and no fast-math. The xxcc build uses
the staged include-path change documented in `feature-compatibility.md`.

The fixtures contain three frames and 36, 39 and 36 columns, totaling 333
binary32 coefficients. Windows MSVC x86_64 maximum normalized differences
are 6.556510925292969e-7 for both MFCC variants and
2.384185791015625e-7 for PLP. Tests retain the measured feature pipeline
bound 2e-5. Raw samples match exactly. The original Lua index parser generates
`index-original.json` through `tests/index_oracle.lua`.

All 23 integration tests pass on Windows MSVC x86_64/i686, Windows GNU
x86_64, and Linux GNU x86_64/i686. This includes both normally ignored host
tests, run with `--include-ignored` and `SHIRO_TEST_LUA` pointing to Lua 5.4.9
and `SHIRO_TEST_SPTK_DIRECTORY` pointing to compiled `tests/sptk_fixture.c`
programs. The latter verifies arguments, stream forwarding and failures; it
does not implement SPTK mathematics. The host processes are 64-bit even when
the Rust caller is 32-bit. Lua 5.1 is not yet tested.
