# Feature extraction compatibility

The native Rust feature API implements the original shiro-xxcc processing. The shiro-xxcc command and rawfloat stream I/O are implemented. The initial Windows GNU build required a missing dlltool.exe through optional terminal-color dependencies. The clap configuration now uses the original plain CLI presentation and retains derive/std/help/usage/error-context/suggestions; all nine current integration tests pass on Windows MSVC x86_64/i686, Windows GNU x86_64, and Linux GNU x86_64/i686.

FeatureOptions retains MFCC, MFBE and PLPCC; order/channel adjustment; integer or fractional hops; sample rate, minimum bandwidth and mel warp; DC, RMS/dB energy, delta and acceleration options. Centers and frame counts use original f32 multiplication/division and integer truncation. Windows are centered and zero-padded, but FFT input is unshifted, as in the C tool. Magnitude and weighted RMS use original scalar products before double square roots. Filterbank output is floored at -15. Cepstral order/DC placement and zero-padded difference kernels match the source. MFBE with include_dc retains the original extra zero column. Decibel energy on silence and its derivative nonfinite values are preserved for compatibility.

The original CLI sample-rate validation checks the wrong variable; the Rust API validates the actual rate. Blackman scalar coefficient rounding can make an endpoint slightly negative. An input impulse whose only frame contribution is at that endpoint produces negative squared RMS in C. Rust clamps negative roundoff to zero before sqrt. An independent two-frame endpoint test verifies this correction; it is separate from unchanged-C comparisons.

## Command and binary streams

shiro-xxcc implements the original -f/-m/-c/-l/-p/-w/-s/-W/-d/-a/-0/-e/-E options. Sample rate uses kHz, fractional hop remains supported, and -E selects RMS for zero or dB for any nonzero value when -e is present. Positional input defaults to stdin; explicit - is also stdin. Combined boolean short flags such as -da are accepted. Successful extraction writes only little-endian rawfloat features to stdout. Errors go to stderr. Generated help exits successfully.

The rawfloat codec reads borrowed streams without seeking, preserves all binary32 bit patterns, retries interrupted reads, carries partial scalars across chunks, enforces a sample budget before output allocation, and rejects an incomplete final scalar. This corrects original seek-dependent piped input and silent trailing-byte truncation. The writer uses write_all and leaves flushing to the caller; commands explicitly flush buffered stdout. I/O and allocation failures propagate as errors.

Tests compare three CLI configurations covering all feature kinds, fractional/integer hops, DC, RMS/dB, delta/acceleration and automatic channel adjustment against original-C fixture output. File and implicit piped-stdin outputs are byte-identical. Explicit stdin, partial input, invalid feature type/hop/rate/order and help are tested. Rawfloat tests cover 9,000 samples with signed zero, infinities, NaN payload and subnormal bits across chunk sizes 1/3/5/17/4096/16384, budgets, partial final scalars, and read/write failures. These tests extend the 72-case extraction API comparisons; they do not establish full real-audio model inference/training acceptance.
